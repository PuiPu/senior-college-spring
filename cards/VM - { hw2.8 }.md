# Question
簡述何謂 Paravirtualization? 在此情況下, XEN 堤供了那些改進?
# Answer
**準虛擬化 (Paravirtualization)** 是一種虛擬化技術，其核心概念是透過修改客體作業系統（Guest OS）的原始碼，使其意識到自己正執行於虛擬化環境中，進而與虛擬機器監視器（VMM）進行協作，以繞過底層指令集架構（ISA）中難以虛擬化的限制,。

在此架構下，**Xen 系統** 針對 IA-32 架構（x86）提供了以下關鍵改進與技術特性：

1. 解決非虛擬化指令問題

- IA-32 指令集中包含一些「關鍵指令（Critical instructions）」，這些指令在使用者模式執行時不會觸發 Trap，導致傳統虛擬化難以攔截,。
- **Xen 的做法**：它定義了一個與底層硬體相似但不完全相同的虛擬機介面。客體作業系統中原本執行特權操作的部分會被替換為對 VMM 的顯式呼叫（Hypercalls），由 VMM 驗證並代為執行。

2. 特權層級的重新配置 (Ring Re-mapping)

- 傳統 IA-32 系統中，OS 核心執行於 Ring 0，應用程式執行於 Ring 3。
- **Xen 的改進**：它利用了 IA-32 具備四個特權環（Ring 0-3）的特性，將 **VMM 運行在 Ring 0**，並修改客體 OS 核心使其執行於 **Ring 1**，而應用程式仍維持在 Ring 3。這種做法避免了 OS 與 VMM 之間的特權衝突。

3. 簡化虛擬化任務與提升效能

- **消除複雜轉換**：由於 OS 已被修改以配合 VMM，Xen 不再需要進行複雜的「掃描與補丁（Scanning and Patching）」或是維護龐大的「陰影分頁表（Shadow Page Tables）」，大幅降低了軟體模擬的開銷。
- **效能優勢**：根據研究，經過 Xen 準虛擬化修改後的 Linux，其變動程式碼量僅不到 3000 行（約 1.36%），但在各項基準測試中的效能可達到原生系統（Native）的 **90% 以上**。

4. 維持應用程式相容性

- 儘管 Xen 需要修改作業系統核心（如 Linux 或 Windows XP），但其設計目標是讓**應用程式二進位檔（Application Binaries）無需任何修改**即可直接在虛擬環境中執行。

**總結來說**，Xen 透過「修改 OS 核心以換取效能」的策略，成功地在原本難以虛擬化的 IA-32 硬體上，實現了極低損耗的虛擬化環境。
