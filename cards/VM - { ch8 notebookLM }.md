這是一份針對 **Chapter 8 (System Virtual Machines)** 的詳盡考試重點整理。本章的核心在於如何讓單一硬體平台同時支援多個完整的客體作業系統（Guest OS）及其應用程式。

--------------------------------------------------------------------------------

**一、 系統虛擬機 (System VM) 的核心定義與動機**

- **定義**：透過虛擬機器監視器（VMM）管理硬體資源，使多個系統映像（System Images）能共享同一組物理資源，且每個客體 OS 都認為自己擁有獨立的硬體。
- **虛擬機器監視器 (VMM)**：擁有硬體最終控制權的軟體層，負責攔截客體 OS 的特權指令並確保隔離性。
- **主要應用**：
    - **資源管理**：實現多工與時間分片（Time-sharing）。
    - **系統轉移與相容性**：過渡到新 OS 或執行舊版（Legacy）程式。
    - **安全與隔離**：將損毀或受攻擊的風險限制在單一 VM 內。
    - **開發與測試**：在不崩潰主機的情況下測試新系統軟體。
    - **系統封裝**：檢查點（Checkpointing）與狀態傾印（Dumping），利於環境遷移。

--------------------------------------------------------------------------------

**二、 虛擬化的理論基礎：Popek & Goldberg 定理**

這是本章最常考的理論重點，定義了 ISA 是否能「高效虛擬化」的充足條件。

1. **指令分類 (Instruction Classification)**：
    - **特權指令 (Privileged)**：在使用者模式（User Mode）下執行會產生 **Trap** 的指令。
    - **敏感指令 (Sensitive)**：
        - **控制敏感 (Control-sensitive)**：企圖修改系統資源配置（如記憶體映射或計時器）。
        - **行為敏感 (Behavior-sensitive)**：其執行結果取決於當前資源狀態（如處理器模式）。
    - **無害指令 (Innocuous)**：不屬於上述兩類的指令。
2. **定理一 (Theorem 1)**：
    - **條件**：當一個 ISA 的**敏感指令集是特權指令集的子集**時，該架構是可高效虛擬化的。
    - **邏輯**：這確保了所有企圖影響系統狀態的操作都會自動觸發 Trap，交由 VMM 攔截並處理，其餘普通指令則直接由硬體執行。
3. **關鍵指令 (Critical Instructions)**：
    - 指那些**「敏感但非特權」**的指令。它們在虛擬機中執行時**不會觸發 Trap**，會導致執行結果錯誤（例如 IA-32 的 `POPF` 指令）。

**三、 處理器與指令虛擬化技術**

針對非虛擬化架構（如 IA-32）的解決方案：

- **二進位翻譯 (Binary Translation, BT)**：
    - VMM 掃描指令流，遇到特殊或關鍵指令時，將其翻譯為等效的目標指令序列（例如修改虛擬 CPU 的標誌位元）。
- **補丁技術 (Patching / Scanning and Patching)**：
    - 在執行前掃描基本區塊（Basic Block），將發現的關鍵指令替換為 Trap 或 Jump 指令，強制控制權轉回到 VMM。
- **模擬碼快取 (Caching Emulation Code)**：
    - 為了避免重複翻譯的開銷，將翻譯後的模擬常式存入 Code Cache。
- **遞歸虛擬化 (Recursive Virtualization)**：
    - 在 VM 中再跑一個 VMM。
    - **定理二 (Theorem 2)**：必須滿足系統可虛擬化，且 VMM 本身不具備時間依賴性（Timing Dependences）。

--------------------------------------------------------------------------------

**四、 資源虛擬化 (Memory & I/O)**

1. **記憶體虛擬化**：
    - **陰影分頁表 (Shadow Page Tables)**：客體 OS 維護「虛擬到真實（V-to-R）」的對應，VMM 則維護「虛擬到物理（V-to-P）」的陰影表，硬體直接使用後者進行地址轉換。
    - **記憶體氣球 (Ballooning)**：透過客體內的驅動程式強迫 OS 釋放不必要的記憶體，以便重新分配物理資源。
2. **I/O 虛擬化**：
    - **設備類型**：專用（Dedicated）、分割（Partitioned）、共享（Shared）或列隊（Spooled）。
    - **層次**：可在系統呼叫層、設備驅動層或 I/O 匯流排層（操作層級）進行攔截模擬。

--------------------------------------------------------------------------------

**五、 硬體輔助技術 (Hardware Assists)**

1. **IBM IEF (Interpretive Execution Facility)**：
    - 核心指令：**SIE (Start Interpretive Execution)**。
    - 運作：VMM 設置狀態描述表後執行 SIE，硬體直接處理大部分特權指令，僅在必要時觸發攔截（Interception）退出回 VMM。
2. **Intel VT-x (Vanderpool)**：
    - **VMX 模式**：分為 **Root 操作**（供 VMM）與 **Non-Root 操作**（供 Guest VM）。
    - **優點**：客體作業系統核心可以直接運行在 **Ring 0**，解決了傳統虛擬化的特權級壓縮（Ring Compression）問題。
    - **VMCS (Virtual Machine Control Structure)**：存放 VM 狀態與執行控制位元的硬體資料結構，自動管理狀態載入/卸載。

--------------------------------------------------------------------------------

**六、 虛擬機類型與特性**

- **原生型 (Native) vs. 裝載型 (Hosted)**：
    - **Native**：VMM 直接跑在硬體上（如 ESX）。
    - **Hosted**：VMM 跑在主機 OS 上（如 VMware Workstation），可直接利用主機的驅動程式。
- **即時遷移 (Live Migration)**：
    - 流程：建立基準拷貝 → 迭代傳輸變動（Dirty）頁面 → 凍結 VM → 傳送最終狀態與處理器狀態 → 在目標端恢復執行。
- **快照 (Snapshots) 與複製 (Clones)**：
    - 方便進行研究測試，提升系統開發效率。
