# Question
請說明 IBM 公司提出的 Interpretive Execution Facility (IEF)是如何運作的?
# Answer
IBM 公司提出的 **詮釋執行功能 (Interpretive Execution Facility, IEF)** 是一種將虛擬化功能從軟體層級（VMM）整合至處理器硬體的技術，其目的是為了大幅提升虛擬機器的執行效能，並使虛擬機器的行為更加可預測。

以下是 IEF 運作方式的詳細說明：

1. 核心指令：SIE (Start Interpretive Execution)

IEF 的運作主要圍繞著 **SIE 指令**。虛擬機監視器 (VMM) 軟體透過執行 SIE 指令，將處理器的控制權交給硬體的 IEF 部分，進入「詮釋執行模式」。

2. 運作流程

在執行 SIE 指令之前與期間，系統會進行以下操作：

- **準備狀態表**：VMM 軟體會先處理任何掛起的中斷，並設置一個指向**狀態描述表 (State Description Table)** 的指標。該表格包含了該虛擬機器的架構狀態（如暫存器數值等）。
- **載入資源**：處理器會根據狀態表載入必要的資源（例如通用暫存器）。
- **硬體直接執行**：一旦進入 IEF 模式，處理器會開始直接執行虛擬機器的指令流。**大多數的特權指令 (Privileged instructions) 會直接由硬體處理**，而不需要跳轉回軟體模擬。
- **例外處理**：I/O 指令以及少數複雜或不常見的指令通常不在硬體支援範圍內，仍需由軟體處理。

3. 暫停與退出機制 (Exit Mechanisms)

硬體詮釋執行會在特定情況下掛起，並將控制權交還給 VMM 軟體。主要分為兩類：

1. **中斷 (Interrupt)**：當產生一個針對 VMM 或其他虛擬機器的中斷時，IEF 會暫停。中斷處理完成後，控制權會回到原先的 SIE 指令處重新開始。
2. **攔截 (Interception)**：控制權會轉移到 SIE 之後的下一條指令。這發生於以下情況：
    - 遇到硬體不支援詮釋的指令（如 I/O 指令）。
    - 執行中發生異常 (Exception)。
    - 偵測到外部設置的攔截條件或特殊情況（例如客體作業系統進入等待狀態）。

3. 狀態更新

在控制權回到 VMM 軟體之前，IEF 硬體會自動更新包含虛擬機器狀態描述的表格，確保軟體能獲得最新的虛擬機狀態。

總結

IEF 透過硬體輔助功能（如計時器輔助、地址轉換繞過技術等），讓虛擬機器的執行速度極度接近原生平台的表現。根據來源數據，導入這類硬體輔助（VM Assists）後，虛擬機器的效能損耗可大幅降低。
