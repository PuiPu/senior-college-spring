# 架構
## pipeline
- 用 pipeline 去增加 ILP (Instruction Level parallelism)
- 但是 pipeline 會產生 hazard，需要解決才能產生正確的結果
	- structural hazard
	- data hazard
	- control hazard
- 隨著 pipeline 的<u>深度</u>增加，hazard 會發生的更頻繁，而且 hazard 會影響 performance
- hazard 解法
	- basic
		- stall (最簡單)
		- forwarding
		- predict (control hazard)
	- advance
		- static scheduling (software)
		- dynamic scheduling (hardware)
- 即便 static scheduling 可以預防一些 hazard ...，但是有很多的情況需要到 run-time 才會知道，所以 dynamic scheduling 還是很重要

## branch prediction
- static prediction
	- 由 compiler 預先決定
	- always taken
- dynamic prediction
	- 利用過去行為預測未來行為
	- branch history table (BHT)
- 1-bit predictor
	- 狀態轉移 : 1(taken) , 2(not taken)
- 2-bit predictor
	- 狀態轉移 : 00(strong not taken) $\rightarrow$ 01 $\rightarrow$ 10 $\rightarrow$ 11(strong taken)
- correlating predictor
	- 利用最近 m 個 branch
	- (m,n) predictor
		- $total \:bit = 2^m \cdot n \cdot Prediction \:entries$
- tournament
	- local predictor + global predictor
	- 用 selector 看哪個比較準
- branch target buffer (BTB)
	- 內容 : (1) branch PC (2) target PC (3) prediction bits
	- 工作階段
## multiprocessors
- flynn classfication
	- SISD
	- SIMD (GPU)
	- MISD (幾乎沒有)
	- MIMD (multi-core CPU，最省電)
- vector processor (SIMD)
	- basic flow
		- load vector $\rightarrow$ vector operation $\rightarrow$ store back
- MIMD
	- 每個 processor 都有自己的 code & data
	- type
		- cluster
		- multi-core
- shared / distributed memory
	- shared memory
		- 所有 CPU 共用一個 memory
		- UMA (Uniform Memory Access)
			- feature : (1) programming easy (2) uniform latency 
	- distributed memory
		- pros : (1) high memory bandwidth (2) low memory latency
		- cons : (1) high communication cost (2) complex programming
- cache coherence
	- 問題 : 兩個 CPU cache 同一份資料
	- informal : 任何讀取都要看到最新寫入
	- 3 個要求
		- 自己寫自己讀一定要看得到
		- 別人寫夠久之後一定看得到
		- writes 必須要有唯一的順序 (write serialization)
- snooping protocol
	- 概念 : all caches 都偷聽 bus $\rightarrow$ 當有人寫資料，大家都知道
- write invalidate
	- 核心 : multiple readers, single writer
	- ex
		- (CPU_A, CPU_B) = (x, x)
		- A 發起 invalidate, (CPU_A, CPU_B) = (valid, invalid)
		- 現在只有 CPU_A 可以進行 write
- write update
	- CPU_A 寫 x=5
	- 直接廣播 x=5
	- 大家同時更新 (write invalidate 比較常見，因為 traffic 比較少)
- large scale multiprocessor
	- snooping 的問題 : CPU 太多時，bus 會爆掉
	- 解法 : directory $\rightarrow$ 紀錄只有誰有這個 block (ex. Block A : CPU1, CPU5, CPU8)
		- 寫入時，只通知真正有副本的人
		- 因此，可以擴充到大型系統 (scable)
- parallelism challenge
	- limit : 不是所有程式都可以平行化 (serial)
	- communication cost : CPU 之間要溝通，遠端 memory access (50 ~ 1000 cycles) 很昂貴
## memory hierarchy
- status
	- hit (in cache)
	- miss (not in cache, need to load from memory)
- 處理 write miss
	- write allocate
		- write miss 時，先把 block 載入 cache，再進行寫入 (fetch on write)
		- write back 使用
	- no write allocate
		- write miss 時，不載入 cache，直接寫到 lower-level memory (write around) $\rightarrow$ 繞過 cache 的意思
		- write through 使用
- cache performance
	-  AMAT (Average Memory Access Time)
		- $AMAT \equiv HitTime + MissRate \cdot MissPenalty$
