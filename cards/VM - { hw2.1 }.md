# Question
請以 Popek & Goldberg 提出的定理解釋何謂 關鍵(或稱臨界)指令(critical instruction)? 針對這類因硬體設計不週延所引發的問題, 利用二進制翻譯(binary translation)技術帶來的做法, 請敘述那兩種不用 source program 進行改善, 針對二進碼指令達到有效虛擬化的技術方案.

# Answer
根據來源檔案，Popek 與 Goldberg 對指令集架構（ISA）虛擬化的定理，以及針對關鍵指令（critical instruction）的技術解決方案說明如下：

1. 以 Popek & Goldberg 定理解釋「關鍵指令」

**Popek 與 Goldberg**（1974）提出了判斷一個 ISA 是否能有效支援虛擬機器的充足條件。他們將與硬體互動的指令分為以下類別：

- **特權指令 (Privileged instructions)**：當處理器處於使用者模式（User mode）執行時會產生 Trap（陷阱/中斷）的指令。
- **敏感指令 (Sensitive instructions)**：包含「控制敏感」和「行為敏感」兩類。
    - **控制敏感**：企圖修改系統資源配置（如記憶體映射或處理器模式）的指令。
    - **行為敏感**：其執行結果取決於資源配置（如所在的實體位址或處理器模式）的指令。

**關鍵指令 (Critical instructions) 的定義：** 根據 **Theorem 1**，一個 ISA 只有在「敏感指令是特權指令的子集」時，才是可以被有效虛擬化的。 所謂的**「關鍵指令」**，就是指那些**「屬於敏感指令，但不是特權指令」**的指令****。這類指令在使用者模式下執行時**不會觸發 Trap**，因此虛擬機器監視器（VMM）無法直接攔截並模擬它們，會導致虛擬機執行結果錯誤，這是硬體設計不週延所引發的問題。

--------------------------------------------------------------------------------

2. 針對二進碼指令的二進位翻譯（Binary Translation）技術方案

對於含有關鍵指令的非虛擬化架構（如 Intel IA-32），無需原始程式碼，可利用與動態二進位翻譯相關的技術來達成有效虛擬化。來源中提到的兩種主要技術方案為：

**方案一：補丁技術 (Patching / Scanning and Patching)**

這是處理「混合虛擬機器（Hybrid VM）」最務實的做法，透過修改執行中的二進碼來實現。

- **做法**：VMM 在客體（Guest）程式執行前掃描其指令流。一旦發現「關鍵指令」，VMM 會將其替換（Patch）為一個 **Trap 指令（系統呼叫）或跳轉（Jump）指令**，使其強制將控制權轉移給 VMM。
- **優點**：原本不會產生 Trap 的關鍵指令現在會主動通知 VMM。VMM 接收到控制權後，會在軟體層級模擬該指令應有的行為，確保系統的等效性。

**方案二：模擬碼快取 (Caching Emulation Code)**

當關鍵指令出現頻率較高時，單純透過 Trap 處理開銷過大，可採用類似程序虛擬機的代碼快取機制。

- **做法**：VMM 不僅掃描單一指令，而是將關鍵指令及其周邊的指令區塊進行**二進位翻譯（Binary Translation）**，轉換成一組專門針對該位置優化的模擬常式。
- **執行流程**：翻譯後的程式碼被存放在 **代碼快取 (Code Cache)** 中。後續程式執行到該處時，會直接透過跳轉表定位到快取中的翻譯塊，以原生速度執行模擬邏輯，避免頻繁觸發 Trap 所產生的 context switch 開銷。

**總結來說**，這兩者都直接作用於二進位執行檔（Binary），藉由**「掃描與替換」**或**「翻譯與快取」**，在軟體層級解決了硬體無法自動攔截敏感指令的問題。
