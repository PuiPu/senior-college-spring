這份針對 **Chapter 3 (Process Virtual Machines)** 的詳盡考試重點整理，涵蓋了程序虛擬機器的架構、相容性、狀態映射、指令與作業系統模擬以及快取管理。

--------------------------------------------------------------------------------

**一、 程序虛擬機 (Process VM) 基本概念與架構**

- **定義**：在主體 (Host) 作業系統之上的 ABI 介面提供一個虛擬環境，支援單個客體 (Guest) 應用程式執行。
- **核心組件**：
    - **Loader (載入器)**：載入客體二進位檔。
    - **Initialization (初始化)**：分配記憶體、設置信號處理常式 (Signal Handlers)。
    - **Emulation Engine (模擬引擎)**：包含詮釋器 (Interpreter) 與翻譯器 (Translator)。
    - **Code Cache (代碼快取)**：存放翻譯後的目標代碼。
    - **Code Cache Manager**：管理快取替換與清理。
    - **Profile Database**：收集執行數據以引導最佳化。
    - **OS Call Emulator**：將客體系統呼叫轉換為主體作業系統的操作。

--------------------------------------------------------------------------------

**二、 相容性 (Compatibility) 的層級與條件**

- **定義**：客體在主體上的行為準確度。排除了效能差異，僅專注於功能的正確性。
- **相容性層級**：
    - **本質相容性 (Intrinsic Compatibility)**：對**所有**程式與資料 100% 準確，達到完全透明。
    - **外在相容性 (Extrinsic Compatibility)**：僅針對**特定子集**（如特定編譯器產生的程式或特定庫）保證相容。
- **充分相容條件**：
    - 狀態等效性不需在每條指令維持，只需在**作業系統控制轉移點** (OS Control Transfer Points，如系統呼叫、Trap) 維持即可。
    - 從 OS 回復執行時，客體狀態必須與原生平台產生的結果一致。

--------------------------------------------------------------------------------

**三、 狀態映射 (State Mapping)**

- **暫存器映射**：
    - **主體暫存器多**：客體暫存器可直接映射到主體暫存器。
    - **主體暫存器不足**：需在記憶體中維護 **Register Context Block**。切換模式時需執行載入/卸載 (Load/Unload)。
- **記憶體位址空間映射**：
    - **軟體轉換表**：類似分頁表，將客體區塊映射到非連續的主體區域，靈活但速度慢。
    - **直接映射 (Direct Mapping)**：
        - **固定位移 (Fixed Offset)**：客體位址 + 固定常數。
        - **零位移 (Zero Offset)**：客體位址與主體虛擬位址完全一致，效能最佳。
- **位址空間共享**：Runtime 軟體必須與客體程式共享同一個主體虛擬位址空間。

--------------------------------------------------------------------------------

**四、 記憶體架構模擬與保護**

- **保護機制**：利用主體 OS 的 `mprotect()` 與 `SIGSEGV` 信號來實現 R/W/E 權限檢查。
- **分頁大小不匹配**：
    - 若客體分頁 < 主體分頁，多個客體分頁會擠在同一個主體分頁。
    - **解法**：採取保守權限策略（取交集最嚴格者），並由 Runtime 處理額外的 Trap。
- **自我修改代碼 (Self-Modifying Code, SMC)**：
    - **基本做法**：將存放翻譯代碼的原始頁面設為「**唯讀**」。
    - **觸發流程**：寫入行為觸發 Trap → Runtime 清除對應的快取翻譯塊 → 暫時改為 R/W → 以詮釋模式執行該區塊 → 回復唯讀保護。
- **保護 Runtime 記憶體**：
    - 在**模擬模式**下，利用硬體保護將 Runtime 的數據/代碼設為不可存取 (No-access)，代碼快取設為唯執行 (Execute-only)。

--------------------------------------------------------------------------------

**五、 指令模擬與效能權衡**

- **效能公式**：Total Time=S+NT (S: 啟動成本, N: 執行次數, T: 穩態執行時間)。
- **階段式模擬 (Staged Emulation)**：
    1. **詮釋階段**：啟動快，但 T 高。同時進行熱點偵測。
    2. **翻譯階段**：當執行次數超過閾值 (Threshold，如 50 次)，翻譯為基本區塊並快取。
    3. **最佳化階段**：極熱點會被組成超區塊 (Superblocks) 並進行深度最佳化。

--------------------------------------------------------------------------------

**六、 例外與作業系統模擬**

- **精確狀態恢復 (Precise State Recovery)**：當發生 Trap 時，需透過**側表 (Side Tables)** 定位 SPC，並視需求重新詮釋原始代碼以重現精確的客體狀態。
- **系統呼叫模擬**：
    - **相同 OS**：透過 **Wrapper (包裝程式)** 進行參數轉換後直接呼叫主體系統呼叫。
    - **不同 OS**：需逐一模擬語義，難度極高且常不完整（如 Wabi 系統僅支援部分 Word/Excel 功能）。
- **回呼函式 (Callbacks)**：Runtime 需攔截 OS 的發送常式 (Dispatch Routine)，確保執行使用者回呼時仍受控於 VM。

--------------------------------------------------------------------------------

**七、 代碼快取管理 (Code Cache Management)**

- **替換策略**：由於區塊大小不等，常用 **FIFO** 或 **LRU** 算法。
- **清理機制**：
    - **滿了就清 (Flush when full)**：簡單但會導致短暫效能下降。
    - **工作集偵測 (Working Set Detection)**：偵測到大量新翻譯需求時主動清理舊翻譯。
